# AniList 人物与角色名称汉化设计

## 目标

为 AniList 的角色、声优和制作人员名称补充简体中文显示，同时满足以下约束：

- 以单人长期使用为前提，不依赖社区持续维护。
- 不引入完整人物数据库，不明显增加脚本体积。
- 不上传账号、列表、搜索记录、浏览历史或本地缓存。
- 外部数据源异常时保留 AniList 原名，不影响页面使用。
- 第一版只处理名称，不翻译人物简介、经历、角色介绍和关系说明。

## 方案选择

采用运行时轻量混合查询：本地纠错表、Wikidata 直接 ID 映射、Bangumi 同作品精确匹配依次补全。

不采用完整数据快照。完整快照会增加仓库体积、构建时间和后续更新成本。不采用 Bangumi 单一来源，因为角色或人物脱离作品上下文时缺少可靠的 AniList 直连映射。

## 数据优先级

1. **本地纠错表**：只存少量经过确认的 AniList 角色/人物 ID 与简体中文名，不承担覆盖率扩充任务。
2. **Wikidata**：使用 AniList Character ID（P11736）和 AniList Staff ID（P11227）直接查询中文标签。
3. **Bangumi**：只处理 Wikidata 未命中的条目，并且仅在当前 AniList 作品存在可靠 Bangumi 条目映射时启用。
4. **AniList 原名**：以上来源均无可靠结果时保持原样。

只有包含汉字的结果才会替换页面名称。繁体结果经过现有 OpenCC 简体转换和大陆用词归一化。

## 运行流程

### 页面扫描

独立的人物名称翻译器扫描带有明确链接的元素：

- `/character/{id}` 识别角色 ID。
- `/staff/{id}` 识别声优或制作人员 ID。
- 处理作品详情页的角色/制作人员卡片、人物详情页标题、收藏列表、个人主页和站内搜索结果。

翻译器只替换名称节点，不触碰角色定位、声优职责、作品标题及页面说明。原名保存在元素属性中，便于路由切换和失败回退。

### Wikidata 主查询

收集当前可见且没有缓存的 AniList ID，按角色和人物分组批量请求 Wikidata。每次请求最多包含 30 个 ID，避免逐条请求。

查询结果必须同时满足：

- 通过对应 AniList ID 属性直接命中。
- 中文标签包含汉字。
- 返回 ID 与请求 ID 一一对应。

不使用姓名模糊匹配。

### Bangumi 补全

仅在作品详情相关页面执行：

1. 通过现有标题补充库取得 AniList 作品 ID 对应的 Bangumi subject ID。
2. 通过 AniList GraphQL 一次取得缺失角色或人物的 native name。
3. 读取 Bangumi 作品的角色/人物列表。
4. 对归一化后的日文原名做完全一致匹配。
5. 只有唯一匹配时才读取该角色或人物详情中的“简体中文名”。

同名多条、原名缺失或匹配不唯一时放弃替换。详情请求只针对当前可见的缺失项，并发上限为 2，不进行后台遍历。

## 缓存与轻量化

使用浏览器本地存储保存查询结果：

- 有效中文名缓存 30 天。
- 未命中结果缓存 7 天。
- 本地纠错表永久生效并覆盖缓存。
- 缓存键包含数据结构版本，升级时可安全失效。

命中缓存时不产生网络请求。每位用户的缓存相互独立，不向项目或其他用户同步。项目不包含遥测、统计上报和中心服务。

页面路由变化时使用递增任务代号忽略旧页面的迟到响应，避免把上一页的人物名写到新页面。

## 组件边界

- `src/data/entities/overrides.ts`：少量人工纠错项。
- `src/entity-name-service.ts`：数据源优先级、缓存和批处理调度。
- `src/wikidata-name-source.ts`：构造 Wikidata 查询并解析直接 ID 结果。
- `src/bangumi-entity-source.ts`：作品上下文内的 Bangumi 精确补全。
- `src/entity-name-translator.ts`：识别 DOM 中的角色/人物链接并安全替换名称。
- `src/chinese-normalizer.ts`：复用简繁转换与大陆用词归一化。
- `src/main.ts`：把人物翻译器接入现有路由和 DOM 观察流程。
- `scripts/userscript-metadata.ts`：加入 `query.wikidata.org` 连接权限并升级脚本版本。

现有通用界面翻译器继续保护角色和制作人员区域，人物名称只由新的专用翻译器处理。

## 错误处理

- 任一外部请求失败时保留当前名称。
- 无汉字、空标签或映射歧义的结果不写入页面。
- 单个条目失败不影响同批其他条目。
- 旧路由响应不更新当前页面。
- 请求队列始终限制并发，避免影响 AniList 正常浏览。

## 隐私边界

脚本没有项目后端，也不上传用户数据。外部查询只包含当前页面公开条目的 AniList ID、Bangumi subject ID 或公开日文原名。AniList 用户名、个人列表、搜索输入、浏览历史和本地缓存均不发送给项目维护者。

## 测试范围

- 从角色和人物链接正确提取 AniList ID。
- 本地纠错、Wikidata、Bangumi和原名的优先级。
- Wikidata 批量查询生成、响应过滤及简体转换。
- Bangumi 日文原名唯一匹配与歧义拒绝。
- 正缓存和负缓存的有效期。
- 并发上限和页面切换后的迟到响应隔离。
- 角色卡片、制作人员卡片、详情标题和收藏/搜索结果的 DOM 替换。
- 完整执行现有 `npm run check`，确保标题、标签、搜索和界面汉化不回归。

## 发布与回滚

第一版在 `codex/entity-localization-v1` 分支开发和验证，不直接改动 `main`。验证满意后再整理为一次稳定发布；效果不理想时删除该分支即可回到当前版本。第一版计划版本号为 `0.1.14`。
